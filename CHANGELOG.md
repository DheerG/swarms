# Changelog

## [Unreleased]

### Changed
- Cost tier is now an explicit pick at setup instead of a silent default. The setup question offers "Defaults — Ultra (Recommended)" / "Defaults — Balanced" / "Configure each step", and the tier picker carries honest copy: Ultra runs the whole team on the stronger model for reliable rule-following (now the recommended pick); Balanced runs cheaper members at the cost of less reliable rule-following. No existing user is silently re-priced — the tier is always chosen. Tier names (Balanced/Ultra) and the spawn-time model mapping are unchanged.
- `/swarm:refine` (a fixed-tier, no-picker command) now defaults to Ultra instead of Balanced — rigorous refinement is where reliable rule-following matters most, and refine has no picker to opt up.
- User-facing vocabulary standardized on "cost tier" (the picker, summaries, and docs previously mixed "shape" and "tier" for the same concept).
- Existing custom-workflow shortcut commands (generated by `/swarm:create-workflow`) keep their previous silent-default setup until you run `/swarm:update-workflow`, which regenerates the setup flow with the new tier pick.

### Added
- `swarm:independent-review-loop` — an optional independent review loop in Code work (code-mode and `/swarm:refine`); its differentiator is independence + exhaustiveness (a reviewer that fails differently from the authors, run to clean), distinct from recursive refinement (the ladder also hunts bugs as it drives completeness; independence run-to-clean is the new axis). At 9/10+, code-mode's Refine presents a unified pre-ship gate (four thoroughness-descending options): *recursive refinement + independent review* / *recursive refinement only* / *independent review loop only* / *ship as is*. For the review options, the loop runs at Deliver **after the ship steps** (PR-then-loop on the common path), reviewing the whole branch diff against the approved outcome each round (base = `main` or the repo's equivalent target; no GitHub PR required); the lead triages findings in/out-of-scope, fixes the in-scope functional ones (committing each round, pushing per the ship definition), and re-reviews until none remain (15-round escalation backstop; oscillation matched by title+`file:line` → surfaced to the user). The engine is an in-skill sub-choice — Codex (independent model, preferred when present; `command -v codex` sets order/default, both engines always offered) or a swarm-native fallback (fresh ephemeral Codex-style reviewer subagents). Codex runs read-only via stdin (`codex exec review -`), depending only on the `codex` binary, never the codex plugin, and warns to disable codex's own Stop review-gate during a run. Reviewer rubric and prose-only finding format adapted from OpenAI Codex (`codex-rs`, Apache-2.0). No new phase, no new hard rules, no briefing-template changes.
- README note clarifying that per-member reasoning effort is not settable — effort is session-global (`/effort`, which also lowers the facilitator), and `CLAUDE_CODE_SUBAGENT_MODEL`, if set, overrides the tier picker by forcing one model for all teammates.
- **"Recursive refinement only" gate option.** A fourth gate option lets a run take the full 9.25→10 ladder without the independent review loop (previously the only ladder option also forced the loop). (code-mode, `/swarm:refine`, and `swarm:independent-review-loop` updated together.)
- **Codex usage-limit auto-wait.** A Codex rate-limit error is now its own class, distinct from auth/fatal failures: the loop parses the reset time and, within a ~5–6h cap (the rolling window), records a `codex-reset-wait` task, announces the wait once, and auto-resumes the same round off the existing pulse — no lost hours when the window is minutes from reopening. Beyond the cap, on an unparseable/weekly reset, or after repeated non-clearing waits, it escalates (wait / Swarm fallback / stop) rather than waiting blind; a watching user can reply to switch to the Swarm fallback immediately instead of waiting.
- **Persisted reviewer engine.** The engine question (Codex vs Swarm fallback) now offers an "always for this project / just this session" follow-up; "always" writes `.claude/swarm-review.md` (mirroring the `swarm-ship.md` ask-once / read-thereafter mechanism). A saved preference selects the engine but never asserts availability — it re-checks at runtime and degrades to the fallback without overwriting the file, so the pref stays portable across machines.
- **Run-state task list (durable spine).** A session-scoped, closed-vocabulary task list (`independent-review-loop pending`, `codex-reset-wait until <T>`) carries the gate pick and the rate-limit wait across long idle gaps and context compaction, so the pulse and Deliver act on durable state rather than recall.

### Fixed
- **Independent review loop could be skipped after the recursive ladder.** When *recursive refinement + independent review* was chosen, the loop was a trailing conditional paragraph in Deliver gated on the lead recalling a choice made many rounds (and possibly a compaction) earlier, with PR-creation reading as terminal — so the run sometimes shipped without ever entering the loop. Deliver is now an ordered ship → loop → terminal definition-of-done, and the loop fires off the recorded `independent-review-loop pending` task, not recall.
- **Pulse kept reviving the lead after a run was done.** The heartbeat cron was deleted only on explicit shutdown, and its idle branch ("advance to your next phase") had no concept of "run over," so it pinged the idle lead every 4 minutes indefinitely post-delivery. Deliver now deletes the pulse at the true terminal (after any independent loop) before asking keep-open/shutdown, and the pulse gained a terminal-aware backstop (self-delete only on a confirmed push/PR observable, never a commit-only run) plus an existence-check so it is never doubled. Governed by two new Team Lead rules (terminal-state, pulse-existence) kept out of the briefing templates. The pulse prompt also notes that the cron fires on a fixed wall-clock schedule (only when idle), so pulses can bunch under 4 minutes apart after a long busy turn — the lead gauges "silent"/"waited" by real elapsed time, not by a pulse firing, avoiding premature re-pings of teammates.
- README model-config section refreshed: the `opus` alias and 1M-context examples now reference Opus 4.8 (was 4.7), and the facilitator effort note no longer pins a specific default value.

## [0.4.0] - 2026-05-01

### Added
- `/swarm:refine` — standalone command that runs recursive refinement on the current branch and pull request against user-stated outcomes. Skips Research/Converge/Approve/Execute and enters at Review → Refine → Deliver. Fixed reviewer roster (Principal Engineer facilitator + Correctness Reviewer, Outcomes Reviewer, Regression Reviewer). Pre-flight reads the current branch, PR (via `gh pr view`), and diff (`git diff <base>...HEAD`) and embeds them in member briefings as raw context. Defaults to Code mode, Balanced shape.
