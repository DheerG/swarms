# Changelog

## [Unreleased]

### Changed
- **Gate presentation is now catalog-driven.** Each lead→user gate is frozen as a constant — question text, header, option labels/descriptions, a question-digest field list, and preview content — projected into three renders (question text / option `preview` / AFK plain-text restatement) under a verbatim-transport contract: runtime fills declared slots and selects among frozen options, never re-authors; an entry may declare an extra AFK carrier that every re-emission must re-carry (Approve re-carries the CONVERGED synthesis verbatim, re-read from the facilitator's on-disk transcript after a compaction — so a held Approve gate never goes blank). The shape is a hybrid: the transport contract, partition rule, and authoring rubric live in `swarm:workflow-rules` (always-resident discipline), while the per-gate constants live in a new `swarm:gate-presentation` skill invoked fresh at each gate and rendered same-turn — byte-exact from disk (a context compaction preserves meaning, not bytes) and composable per the plugin's own skill convention. launch.md Steps 2/4/7, `/swarm:refine` Step 3, both generated-workflow templates, and the mode skills' Approve/Finish/Refine/Terminal gates now render from the catalog instead of re-deriving presentation inline (~12 per-site re-derivations → 1 definition). Two intended visible changes: a gate's question text no longer restates its preview — the question carries decision handles, the preview carries the elaboration (partition rule: no field in two carriers at the same fidelity), and the Approve gate now carries the CONVERGED synthesis in the modal preview itself, where it stays readable while the modal has focus; and the tier labels now carry their deciding axis — "Ultra — reliability (Recommended)" / "Balanced — lower cost" — per the catalog's label rule (persisted token + short axis; consequence and cost in the description). Behavior otherwise unchanged; briefing templates untouched; pre-change generated shortcuts keep old wording until their repo runs `/swarm:update-workflow`.
- **Streamlined default path.** `/swarm:launch` and the mode shortcuts walk the observed default pathway and nothing else: outcomes → an explicit tier pick ("Ultra — reliability (Recommended)" / "Balanced — lower cost") → the suggested team presented for approval ("Does this team look right?" — point at a member to swap it, add more, or trim) → the full Team Plan behind "Launch the team". The "Configure each step" walk-through is retired (100% of observed launches took defaults); its per-setting definitions survive as a compact Adjustments Reference behind "I have changes". Passing outcomes inline with the command skips only the outcomes prompt — never the tier, team, or launch gates. (An earlier iteration collapsed setup to a single tier-carrying launch gate; it dropped the team-shape approval and left one stop between inline outcomes and spawn — in a real run the lead blew through it and spawned without asking the tier. Superseded by this flow.)
- **Mode shortcuts are thin delegates.** `/swarm:code`, `/swarm:triage`, `/swarm:write`, and `/swarm:workflow` now execute launch.md with overrides (mode, outcomes question, context) instead of re-implementing the setup flow inline — so they can no longer drift from the canonical flow. (They had drifted: after #77 reordered launch.md to outcomes-first, the shortcuts kept asking setup-first.)
- **Single-source governance.** `skills/workflow-rules/SKILL.md` is now the canonical home of the hard rules, briefing templates, launch mechanics, run-state/pulse setup, and universal execution rules; launch.md invokes it at Step 1 as "the governance spec" instead of mirroring it. Removes ~4k words of hand-synced duplication and the whole sync-failure class (the mirror had already drifted on the Triage ship-check exemption).
- **Claude Code v2.1.178 or newer is required.** The TeamCreate/`team_name` version branch is dropped — teams always form implicitly at the first member spawn.
- Maintainer commentary (HTML comments) moved out of shipped command files into an AGENTS.md Maintainer Notes section, with a standing rule against dev-meta in shipped files.
- **Heartbeat pulse cadence 4 min → 20 min.** The lead's idle heartbeat fires every 20 minutes instead of every 4, so a long or overnight wait no longer accumulates ~a hundred idle wake-ups, and each fire carries enough elapsed time to be a decisive recovery signal rather than a premature "too soon" no-op. Accepted cost, disclosed: the slower cadence slows ALL pulse-driven recovery to ≤20 minutes — not only the gate case, but also auto-recovery from a cut-off turn, re-pinging a silent teammate, and resuming a Codex rate-limit wait. The pulse is now identified by its prompt-prefix alone (not its schedule), so a leftover pulse from a different cadence stays findable; and while a decision-grade gate is pending, the pulse re-states it in full on each fire so it survives a context compaction.
- Cost tier is now an explicit pick at setup instead of a silent default. The setup question offers "Defaults — Ultra (Recommended)" / "Defaults — Balanced" / "Configure each step", and the tier picker carries honest copy: Ultra runs the whole team on the stronger model for reliable rule-following (now the recommended pick); Balanced runs cheaper members at the cost of less reliable rule-following. No existing user is silently re-priced — the tier is always chosen. Tier names (Balanced/Ultra) and the spawn-time model mapping are unchanged.
- `/swarm:refine` (a fixed-tier, no-picker command) now defaults to Ultra instead of Balanced — rigorous refinement is where reliable rule-following matters most, and refine has no picker to opt up.
- User-facing vocabulary standardized on "cost tier" (the picker, summaries, and docs previously mixed "shape" and "tier" for the same concept).
- Existing custom-workflow shortcut commands (generated by `/swarm:create-workflow`) keep their previous silent-default setup until you run `/swarm:update-workflow`, which regenerates the setup flow with the new tier pick.

### Added
- **Documented limitation — Fable-tier lead.** When the lead session runs on Fable, member spawns are served the lead's Fable model even though swarm requests the tier's model correctly (`opus`/`sonnet` — the request is transmitted and resolved, then not honored by the serving layer; upstream Claude Code issue, observed-consistent on v2.1.198 for both tiers). No swarm-side fix or warning — documented in AGENTS.md Maintainer Notes with a revisit hook. Leads on Opus (the common case) are unaffected.
- `swarm:independent-review-loop` — an optional independent review loop in Code work (code-mode and `/swarm:refine`); its differentiator is independence + exhaustiveness (a reviewer that fails differently from the authors, run to clean), distinct from recursive refinement (the ladder also hunts bugs as it drives completeness; independence run-to-clean is the new axis). At 9/10+, code-mode's Refine presents a unified pre-ship gate (four thoroughness-descending options): *recursive refinement + independent review* / *recursive refinement only* / *independent review loop only* / *ship as is*. For the review options, the loop runs at Deliver **after the ship steps** (PR-then-loop on the common path), reviewing the whole branch diff against the approved outcome each round (base = `main` or the repo's equivalent target; no GitHub PR required); the lead triages findings in/out-of-scope, fixes the in-scope functional ones (committing each round, pushing per the ship definition), and re-reviews until none remain (15-round escalation backstop; oscillation matched by title+`file:line` → surfaced to the user). The engine is an in-skill sub-choice — Codex (independent model, preferred when present; `command -v codex` sets order/default, both engines always offered) or a swarm-native fallback (fresh ephemeral Codex-style reviewer subagents). Codex runs read-only via stdin (`codex exec review -`), depending only on the `codex` binary, never the codex plugin, and warns to disable codex's own Stop review-gate during a run. Reviewer rubric and prose-only finding format adapted from OpenAI Codex (`codex-rs`, Apache-2.0). No new phase, no new hard rules, no briefing-template changes.
- README note clarifying that per-member reasoning effort is not settable — effort is session-global (`/effort`, which also lowers the facilitator), and `CLAUDE_CODE_SUBAGENT_MODEL`, if set, overrides the tier picker by forcing one model for all teammates.
- **"Recursive refinement only" gate option.** A fourth gate option lets a run take the full 9.25→10 ladder without the independent review loop (previously the only ladder option also forced the loop). (code-mode, `/swarm:refine`, and `swarm:independent-review-loop` updated together.)
- **Codex usage-limit auto-wait.** A Codex rate-limit error is now its own class, distinct from auth/fatal failures: the loop parses the reset time and, within a ~5–6h cap (the rolling window), records a `codex-reset-wait` task, announces the wait once, and auto-resumes the same round off the existing pulse — no lost hours when the window is minutes from reopening. Beyond the cap, on an unparseable/weekly reset, or after repeated non-clearing waits, it escalates (wait / Swarm fallback / stop) rather than waiting blind; a watching user can reply to switch to the Swarm fallback immediately instead of waiting.
- **Persisted reviewer engine.** The engine question (Codex vs Swarm fallback) now offers an "always for this project / just this session" follow-up; "always" writes `.claude/swarm-review.md` (mirroring the `swarm-ship.md` ask-once / read-thereafter mechanism). A saved preference selects the engine but never asserts availability — it re-checks at runtime and degrades to the fallback without overwriting the file, so the pref stays portable across machines.
- **Run-state task list (durable spine).** A session-scoped, closed-vocabulary task list (`independent-review-loop pending`, `codex-reset-wait until <T>`) carries the gate pick and the rate-limit wait across long idle gaps and context compaction, so the pulse and Deliver act on durable state rather than recall.

### Fixed
- **Setup gates could pass while showing the user nothing.** The team-approval and launch-confirmation gates put the roster and Team Plan in prose next to the AskUserQuestion — but a focus-capturing modal renders over same-turn prose, so a user could be asked "Does this team look right?" having seen no team, and "Is this plan final?" having seen no plan (observed in a live run, twice, with the prose fully rendered). The decision content now rides inside the question text of the modal itself — every member named with its identity line at the team gate, the full Team Plan verbatim at the launch gate, decision-critical lines front-loaded — and a prose-only render no longer satisfies either gate. Bound consistently across launch.md, workflow-rules, and both generated-workflow templates; briefing templates untouched.
- **Decision-grade gates no longer silently vanish when you step away.** A recent Claude Code change auto-resolves an AskUserQuestion modal after 60s if the user is away, returning a "proceed using your best judgment" sentinel in place of a chosen option — so a long-running gate (Approve, refine-or-deliver, the launch confirmation, final sign-off) could auto-advance on nobody's answer. The lead now treats that sentinel as unanswered (never as consent) and re-issues the gate as durable plain-text — every option with its consequence, answerable by naming the whole option or a shorthand — so a complex gate can be answered precisely without the modal. This recovery is load-bearing, not an edge case: a quiet gate WILL hit the 60s cutoff (nothing resets the idle timer, and the heartbeat can't rescue it), so the plain-text restatement is the primary path whenever you're away — not a rare fallback. Also fixes a carve-out that left the pre-spawn launch confirmation unprotected. Mirrored across launch.md and workflow-rules.
- **Independent review loop could be skipped after the recursive ladder.** When *recursive refinement + independent review* was chosen, the loop was a trailing conditional paragraph in Deliver gated on the lead recalling a choice made many rounds (and possibly a compaction) earlier, with PR-creation reading as terminal — so the run sometimes shipped without ever entering the loop. Deliver is now an ordered ship → loop → terminal definition-of-done, and the loop fires off the recorded `independent-review-loop pending` task, not recall.
- **Pulse kept reviving the lead after a run was done.** The heartbeat cron was deleted only on explicit shutdown, and its idle branch ("advance to your next phase") had no concept of "run over," so it pinged the idle lead every 4 minutes indefinitely post-delivery. Deliver now deletes the pulse at the true terminal (after any independent loop) before asking keep-open/shutdown, and the pulse gained a terminal-aware backstop (self-delete only on a confirmed push/PR observable, never a commit-only run) plus an existence-check so it is never doubled. Governed by two new Team Lead rules (terminal-state, pulse-existence) kept out of the briefing templates. The pulse prompt also notes that the cron fires on a fixed wall-clock schedule (only when idle), so pulses can bunch under 4 minutes apart after a long busy turn — the lead gauges "silent"/"waited" by real elapsed time, not by a pulse firing, avoiding premature re-pings of teammates.
- README model-config section refreshed: the `opus` alias and 1M-context examples now reference Opus 4.8 (was 4.7), and the facilitator effort note no longer pins a specific default value.

### Removed
- **`/swarm:general` retired.** General mode was never picked explicitly in practice. It survives as the silent inferred fallback for outcomes that fit no specific mode ("None of these" in the mode question) and as a wrapper base for custom workflows; the `general-mode` skill is functionally unchanged. Also fixed while in there: onboard.md's mode walkthrough now includes Triage (it was stale, listing only Code/Writing/General), and audit-context's built-in skill collision list now includes `triage-mode`, `reflect-outcome`, and `independent-review-loop`.
- **`swarm:refine-outcomes` retired.** The no-arg `/swarm:launch` flow now opens straight to the outcomes prompt (dropping the "provide outcomes vs. help me build them" fork), and `/swarm:refine`'s plan-confirm drops its "Help me frame these as outcomes" option. The reframe-help path went unused; it is no longer offered.

## [0.4.0] - 2026-05-01

### Added
- `/swarm:refine` — standalone command that runs recursive refinement on the current branch and pull request against user-stated outcomes. Skips Research/Converge/Approve/Execute and enters at Review → Refine → Deliver. Fixed reviewer roster (Principal Engineer facilitator + Correctness Reviewer, Outcomes Reviewer, Regression Reviewer). Pre-flight reads the current branch, PR (via `gh pr view`), and diff (`git diff <base>...HEAD`) and embeds them in member briefings as raw context. Defaults to Code mode, Balanced shape.
